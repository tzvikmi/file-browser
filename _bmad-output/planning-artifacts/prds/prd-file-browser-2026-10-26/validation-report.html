The grade reflects the rubric formula, not these testability gaps.

Adversarial review

review-adversarial.md

21 findings, no severity by design. FR-1, FR-4 and FR-7 are owner-verbatim, so guards target the surrounding text. Findings are condensed here; the full text is in the source file.

FR-4 identity contradicts the "unreadable" definition

FR-4 consequences, Glossary
"Unreadable" includes symlinks and unopenable folders, which are not files to check, so checked + unreadable can exceed the total.
Fix: Count only unreadable files that were in the total; report folders and symlinks separately.

The total is unknown when first displayed

Glossary "File to check", FR-4
Emptiness cannot be known for a file that cannot be opened, and nothing can be counted inside an unopenable folder.
Fix: State when the total is fixed, or that unknowable files count as unreadable.

A file counted "checked" can later turn out unreadable

Glossary "Checked", FR-4, FR-7
A read failure can happen after a file was matched or decided unique by size; double counting breaks the FR-4 identity.
Fix: A file is counted exactly once; a failure moves it to unreadable and removes it from any shown group.

FR-4's test is not deterministic from behaviour alone

FR-4 Test and example
"Slow comparison" and "2 of 4 after two files" assume an order and granularity. FR-4 is owner-verbatim, so the guard targets the surrounding text.
Fix: Add observable checks: the count never decreases, never exceeds the total, starts at 0 and ends at the total.

The Glossary leaks the size pre-filter

Glossary "Checked", addendum
Behaviour-only PRD encodes the brief's pre-filter, which the addendum leaves for the architect to confirm.
Fix: Reword: a file counts as checked once the app has determined whether it has an identical twin.

"Full path" cannot be produced as written

FR-1, FR-7, UJ-1
Browser folder access exposes only paths relative to the picked folder, never the absolute disk path.
Fix: Define "path" in the Glossary as relative to the open folder and replace "full path".

Responsiveness and cancel bound are under-specified

FR-6, FR-5
The bound is tested on one example; a few huge files can block cancel as well as many small ones; "scroll" is untestable before results exist.
Fix: Restate for any folder size; add a one-huge-file test case.

FR-1 and FR-5 conflict on completeness

FR-1 vs FR-5, FR-3
FR-1 says the app lists each group; FR-5 allows missing groups after a cancel; timing of results is not stated.
Fix: State in 4.1 that a cancelled scan lists only confirmed groups and groups may appear while running.

Progressive display conflicts with "one group of three, never pairs"

FR-1 consequences, FR-5
A pair could be on screen before the third copy is found; a cancel then leaves a pair.
Fix: State that a group may lack members until the scan ends, but is never split in a finished scan.

Wasted space is silently low when files are unreadable

FR-3, FR-7
Only the cancel case is marked partial; an unreadable twin leaves an unmarked, understated figure.
Fix: Mark the figure possibly incomplete and show the unreadable count next to it.

Size display is not specified enough to test

FR-3, FR-1
No unit base, rounding or position; "at the top" appears only in UJ-1.
Fix: Define the format in the Glossary and move the position into FR-3.

Skip-list entry semantics are undefined

FR-8, FR-9, §8
Nothing says what may be added (name or path, wildcards, empty, duplicates); case matching blocks a test.
Fix: Define entries as a single folder name, reject empties and duplicates, exact matching; tests use lowercase until decided.

Skip-list edge cases: files, symlinks, locked skipped folders

FR-8, Glossary
A file or symlink named like a skipped folder, or a locked skipped folder, may add noise to the unreadable list.
Fix: A skipped folder is never opened, so never reported unreadable; skipping applies to folders only.

Scan lifecycle is undefined

FR-1, FR-5, FR-9, UJ-1
Start with no folder, double start, previous results on a new scan, folder change mid-scan, skip-list edits after a scan.
Fix: Add a short lifecycle rule.

Empty and degenerate outcomes have no display

FR-3, FR-4, FR-2
No files to check, or no groups: is it "0 of 0", a message, or silence? Does the final count stay on screen?
Fix: Say "no duplicates found" and keep the final count visible.

Unreadable summary on cancel and for changing files

FR-7, FR-5
Not stated whether the list appears after a cancel, how files that change mid-scan are treated, or how a tester makes a file unreadable.
Fix: Show the list at scan end and after cancel; add a test setup line.

"Unreadable" includes readable things; symlink rule is post-brief

Glossary, brief vs FR-7
The symlink rule is a decision taken after the approved brief (owner-confirmed); the browser API may not expose symlinks.
Fix: Mark it as a post-brief owner decision; waive the test where symlinks are not exposed.

Read-only and no-network are not requirements

Vision, §5, SM-1, addendum
The top-priority promise has no FR and no pass/fail check.
Fix: Add an FR: the app does not modify the open folder and makes no network requests; test by comparing the folder before and after.

Hard links count as wasted space

Glossary, FR-3
Two names for the same data match byte for byte, but deleting one frees nothing.
Fix: Note that hard links are treated as separate files and the figure may overstate.

SM-1 is a one-time single-folder check; SM-C1 is not measurable

§7
The test folder is never described and nothing measures a missed copy.
Fix: Describe the test folder contents; reword SM-C1 as a measurable guardrail.

Requirement style and numbering are uneven

FR-1 to FR-9
Only FR-1, FR-4, FR-7 use EARS; "can cancel" is not testable as an obligation; one missing blank line before FR-7.
Fix: Rewrite the other FRs in EARS wording; fix the blank line.
